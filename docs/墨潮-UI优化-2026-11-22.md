## 2. UI 设计规范变更

### 2.1 尺寸与字号（`--rg-*`，一处改全盘走）

| 令牌 | 值 | 用途 | 1920 / 1366 / 1024 实测 |
| --- | --- | --- | --- |
| `--rg-fs-micro` | `clamp(11px, .68vw, 12px)` | 注记、标签、chips | 12 / 11 / 11 |
| `--rg-fs-xs` | `clamp(12px, .82vw, 13.5px)` | 元信息、对比数值 | 13.5 / 12 / 12 |
| `--rg-fs-sm` | `clamp(12.5px, .92vw, 15.5px)` | 正文、卡片描述 | 15.5 / 12.57 / 12.5 |
| `--rg-fs-md` | `clamp(14px, 1.06vw, 17px)` | 等级、辅助读数 | 17 / 14.5 / 14 |
| `--rg-fs-lg` | `clamp(17px, 1.35vw, 22px)` | 卡片名、斩杀数 | 22 / 18.4 / 17 |
| `--rg-fs-xl` | `clamp(20px, 1.7vw, 27px)` | 计时 | 27 / 23.2 / 20 |
| `--rg-fs-hero` | `clamp(24px, 2.3vw, 38px)` | 换屏标题「落笔/开箱/停笔」 | 38 / 31 / 24 |
| `--rg-gap / gap-s / pad / pad-s` | `clamp(10, .95vw, 18)` / `clamp(6, .5vw, 10)` / `clamp(14, 1.35vw, 26)` / `clamp(10, .85vw, 16)` | 间距与内边距 | — |
| `--rg-bw` | `3px` | 顶栏与面板描边 | 3 |

**规则**：不再出现 8–10px 的正文级字号；低于 11px 只允许纯装饰（如 pips 方块）。所有 clamp 下限即 1024 宽的最终值。

### 2.2 语义色（升级类型，不是物品本色）

| 类型 | 令牌 | 值 |
| --- | --- | --- |
| 武器 | `--rg-sem-weapon` | `#3f5c86` |
| 被动 | `--rg-sem-passive` | `#4f7757` |
| 进化 | `--rg-sem-evolve` | `#b5342b` |
| 补给 | `--rg-sem-fill` | `#8a6a3a` |

卡片左侧 7px 色条、glyph 底、类型标签、数字键选中态、阴影全部取 `--sem`；宝箱卡保留物品本色（`--c`），因为那里要认「东西」而不是「类型」。

### 2.3 面板尺寸

| 面板 | 宽度 | 备注 |
| --- | --- | --- |
| 升级「落笔」 | `min(1220px, 100%)` | 卡 375–385 宽，三列等宽等高 |
| 宝箱「开箱」 | 1100 | 卡高 112–148（原 132–168，底部空白过多） |
| 商人 | 1080 | 三件商品一列读价格 |
| 暂停「停笔」 | 820（原 980） | 内容少，收窄才不空 |
| 通用/墨库 | 980（原 1180） | — |

卡片 `min-height` 从 `clamp(212px, 27vh, 282px)` 收到 `clamp(206px, 21vh, 244px)`：大屏上原本描述与「现在/升级后」之间会空出约 90px 的死白。

### 2.4 顶栏结构

一行五段，用 flex 拉开层级，不再所有数据同一字号：

```
[角色 + Lv 徽章 / 经验条 + 读数]   [血条（弹性吃中段）]   [计时 00:00 / 关卡]   [斩 / 墨 / 连]   [冲 / ♪ / ⏸]
```

- 等级徽章 17px（原 13），经验条高 8–9px、带 `8 / 14` 读数；
- 计时为第二重心（27px），关卡名 11px 注记；
- 斩杀数 22px 为主读，金币与连击同字号但颜色分主次（连击热了才转朱）；
- Boss 血条内嵌顶栏第二行，`is-on` 才占位，不挤常驻读数。

### 2.5 底栏（机台页脚）

`engine.ts` 为 rogue 写 `<b>WASD</b> 走位<i>·</i>…` 键帽结构，`rogue.css` 用 `.modal[data-game="rogue"]` 定向放大到 11–13px（`.m-hint / .m-count / .m-btn span`）。**没有改 `hall.css` 全局页脚**，其它机台不受影响。

## 3. 交互实现情况

### 3.1 升级 / 宝箱卡五态

| 状态 | 触发 | 表现 |
| --- | --- | --- |
| 默认 | — | 纸色底、2px 墨边、`5px 5px` 实阴影、左侧语义色条 |
| 悬停 | `:hover` | 位移 `-3,-3`、阴影加到 8px、底色转 `#fffdf4`；不缩放 |
| 键盘聚焦 | `:focus-visible` | 3px 语义色外圈 + 内圈，仅键盘可见 |
| 选中 | `.is-current` | 底色 `#fff6dd`、内嵌 2px 语义色边、数字键块反色 |
| 提交中 | `.is-picked` | 下沉 `3,3`、阴影归零、右下角盖「已落笔」印，110ms 后提交 |
| 不可选 | `.is-disabled` / `.is-poor` | 降饱和 + 灰阴影 + 手型改 `not-allowed`，点击只 toast |

### 3.2 键鼠完整映射

- `← → ↑ ↓` 循环切换选中卡（捕获阶段，不会漏给战场）；
- `Enter` / `Space` 落定当前选中卡；焦点在同一屏的「重摇」等按钮上时让给原生点击；
- `1`–`9` 直选第 N 张（升级、宝箱都生效）；
- `R` 重摇（仅升级）；
- 面板打开即把焦点放到第 1 张卡，`aria-selected` 同步，容器 `role="listbox"`；
- 鼠标 hover 不改选中（`is-current` 由点击/键盘决定），避免“鼠标扫过就换选”。

### 3.3 其它交互修补

- `P` 改为暂停/继续开关（原来暂停面板里只能点按钮，键盘 P 按了没反应）；
- 升级卡「现在 / 升级后」两行来自真实数值：武器按 `dmg / cd / count / pierce` 算增量 chips（`伤害 +5.4`、`间隔 -0.1s`、`穿透 +0.5`），被动写 `Lv.n · 效果`，补给写金币/生命前后值；
- 卡片等级刻度（pips）按真实 `max` 画：被动满 1/4/5/6/8 级各不相同，补给卡不画；
- 页脚提示加 `1-3 选升级`，与实际键位一致。

## 5. 尚未解决 / 需要知情

1. 仓库级 `tsc --noEmit` 仍会失败：未跟踪的 `src/themes/hall/legion/`（另一个并行开发的机台）里 `draw.ts:322` 两句调用挤在一行，缺分隔符。不是本次改动引入，也没动它。
2. `Esc` 在升级/宝箱层不关闭面板：`RogueHandle.escape()` 对这两层返回 `true` 但不关，是有意的「必须三选一」。若希望 `Esc` 退回战场，需要产品侧确认。
3. 进化的「现在 / 进化后」目前用 `WeaponLevel` 字段拼行；进化后的特殊效果（分裂、烧灼等）仍只在描述里，没有单独列 chips。
4. 宝箱卡没有「升级前/后」数值，只有奖励说明（回血 45%、重摇 +2、随机武器 +2 级）。
5. 本次只做电脑端；`pointer: coarse` 的竖屏/横屏布局按原样保留，未重排。
6. 1024×640 下升级面板 999 宽已接近满屏（左右各 12px），若要更宽需改机台外框留白，属于布局层的取舍。
