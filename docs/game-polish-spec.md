# TxxT 小游戏厅 · 第二轮精品化：品质规范与协作契约

> 本文件是这一轮 12 款游戏改造的**唯一视觉/反馈/证据口径**。任何 subagent 在动手前必须先读它；
> 与需求正文冲突时，以"保留核心规则"为先，规则见 §7。

## 0. 不可动的边界

- 仓库根 `D:\Projects\TxxT-Play`，前端在 `site\`。现役代码在 `site\src\themes\hall\`，**不要**碰 `site\paper.html`。
- `site\src\themes\hall\legion\`（纸上军团）**只读**，另有独立升级在进行，任何写入都算事故。
- 首页 13 款顺序、01/02 区块、下载入口、整屏机台开合：一律不改（`Hall.tsx` 除非该任务明确要求，否则不动）。
- 不新增第三方依赖（只有 react/react-dom/playwright-core）。
- 验收钩子语义必须原样保留：`#onetStage.__probe/__tiles/__link`、`#pile.__probe/__sol`、`sameLayer`、`#brkStage.__probe`、`BK.__probe`、`MG_STAGE.__probe`、`TAP_BOARD.__probe`、`RUN.__probe`、`STK.__probe`、`window.__FX/__SFX/__loops`。

## 1. 视觉语言（B · Neo-brutalism Lite）

纸 `#fff8e8`、墨 `#252525`、朱 `#f28b82`、黄 `#ffd166`、蓝 `#9cc7f5`、灰纸 `#efe9da`。
粗边框 + 硬阴影（无模糊投影）+ 纸张层叠感。新增元素一律先问："这是印在纸上的一块东西吗？"
禁止：玻璃拟态、紫色渐变、霓虹光晕、圆角胶囊化、漫反射阴影。

## 2. 三档反馈（每一处新增特效都必须归属某一档，并能说清为什么不是另一档）

| 档 | 触发 | 粒子预算 | 时长 | 声音 | 停顿/震屏 |
|---|---|---|---|---|---|
| 普通 | 单击、选中、悬停确认、普通碰撞、翻牌 | ≤8 片、单一 kind、同侧 | 120–260ms | 短促单发（`SFX.play`，rate 微调） | 无 |
| 重要 | 一次消除/合成/精准命中/接住掉落/连击上跳 | 12–26 片，两种 kind 组合（碎 + 火星 或 墨点 + 环） | 260–520ms | 专属音色 + 半音上扬 | `freeze(40–80ms)` 或 `shake(2–4px)` 二选一 |
| 重大 | 连锁/多行多列/进化/Boss 破阶段/破纪录/通关 | 三层：环 + 主体碎 + 飘字/连击读数，允许一次 `freeze(90ms)` | 600–1100ms，可分两拍 | `fanfare` 或组合音序 | 至多 `shake(5px)`，**不得**超过两拍 |

- 粒子尺寸必须与主体尺寸相关（已有 `burst` 按 rect 尺寸算 size，别越级手写固定 20px 碎片）。
- **每款游戏的"重要/重大"必须长得不一样**：不允许全厅共用同一种"炸开"。各台专属表达登记在 §4。
- 特效层永不参与判定：`pointer-events:none` 已有，新增 DOM 特效同理；不得覆盖可点区域中心。
- `prefers-reduced-motion` 下减半/关震屏由 `fx.ts` 统一处理，新增原语必须走同一个 `reduced` 开关。

## 3. 共享层契约（`site\src\themes\hall\fx.ts` / `sfx.ts`）

- 粒子机器、对象池、预算自适应、DPR 上限、空闲停帧**只在 fx.ts 里有且只有一份**。
- 各台需要新"画法"时：优先组合现有 `burst/burstAt/sparks/ring/trail/rise/pop/combo/freeze/shake`；
  确实需要新运动语义（如"向心聚合""折线闪"）时，由该台在**自己的模块**里写"编排层"（谁在什么时刻调用哪些原语、用什么颜色/尺寸/节奏），
  **不要**复制粒子池、不要新开第二张全屏画布。
- 每台一个 `fx` 编排文件（例如 `games/onet/fx.ts`），只导出该台的 `hit/link/clear/chain` 这类语义函数，内部转调共享原语。
- 音效：新增音色用 `SFX.play(name,{rate,gain})`，name 必须在 sfx.ts 的音表里（需要的音色先在 sfx.ts 的**同一张音表**追加，禁止各自 new AudioContext）。

## 5. 证据规范（每个 subagent 必交）

```
site\.qa\evidence\<game>\
   before-<scene>.png      改前截图（自己先拍）
   after-<scene>.png       改后截图
   run.log                 实际执行的命令 + 关键数字（帧率/耗时/断言）
   notes.md                十项汇报（模板见 §6）
```
- 命令必须可复现：写清端口（`$env:QA_URL='http://localhost:<port>/'`）、脚本名、断言输出。
- 性能数字只认脚本实测：`FX.perf()` / `__loops` / rAF 采样 / `performance.now()`；禁止"感觉流畅"。
- 清理必须实测：进游戏 → 退出 → 500ms 后 `window.__loops` 与 rAF 计数不再增长、无残留 `setInterval`。

## 7. 规则红线（改玩法也不能碰）

- 写了个写：五关牌数/层数、每局有解、同字三张不同层、槽位数量、`#pile.__sol`、`sameLayer`。
- 连字：最多两拐、外圈留白、三关牌数、无解兜底（洗牌/开洞）。
- 破砖：七关、碰撞准确、掉落可接、成败判定。
- 砖块：8×8、三块待放、整行整列消除、双消三消反馈、画面与逻辑同步。
- 垒塔：真实中心判定、外露部分真实掉落、镜头跟随。
- 叠山：汉字等级顺序、同级才合并、分数规则、键鼠/滑动。
- 稿纸/专注：真实竖排、中文输入法组词不提前提交、回车换列 vs ⌘/Ctrl+回车落印、收束。
- 抽词：三档难度、3 秒倒数、易/中预展、零失误获胜、步数耗尽失败。
- 敲印：4×3、金印加命上限 5、墨印陷阱、每 12 命中进阶段、第 4 阶段双印。
- 墨潮：12 武器 8 级 + 进化、19 被动、5 角色、5 Boss、11 永久升级、18 成就、Boss tier 循环、局外上限、存档。
- 走墨：固定步长 1/120、速度曲线、土狼时间、跳跃缓冲、二段跳、障碍可通过。

## 8. 模块拆分契约（地基，由拆分任务落地）

```
hall/
  engine.ts            只保留 attachHall 生命周期、机台开合、路由、键盘总闸
  core/ctx.ts          HallCtx 类型 + 全台共用小工具 + BEST 读写 + 尺寸适配
  games/paper.ts focus.ts pile.ts word.ts brick.ts break.ts onet.ts merge.ts tap.ts run.ts stack.ts
  games/*.css          各台样式（从 hall.css 原样搬移，hall.css 保留 @import 顺序）
```
- 每台导出 `mount<Game>(ctx)`，返回 `{ open, close, replay?, stop, escape? }`，与现在 `ROGUE/LEGION` 同形。
- 拆分本身**零行为变化**：拆前拆后同场景截图逐像素一致（≤1% 像素差），探针输出一致，`npx tsc --noEmit` 通过。
- 之后每款游戏的改造只准写自己的 `games/<game>.ts` / `games/<game>.css` / `games/<game>/fx.ts`。
