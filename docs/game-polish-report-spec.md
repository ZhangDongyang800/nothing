## 0. 硬约束
- 图片一律**内嵌**为 `data:image/jpeg;base64,...`（每张压到宽 ≤1400px、质量 ~82，单张 ≤250KB），HTML 内不得出现任何外部 http 链接做图片源。
- 不引用任何 CDN 字体/脚本；只用系统字体族。
- 不修改 `site\src` 下任何源码；只写 `docs\` 与临时目录。
- 所有结论必须带实测数字（探针 JSON / run.log 里能查到的），禁止「更流畅」「更丰富」这类无据形容。
- 每台必须写「未解决/遗留」一节，如实照抄各台 notes.md §10 的条目，不许美化或删除。

## 3. 每台一节，固定十项
表格或分行，标题用台名 + 一句话定位：
1. **玩法深度**：新增的机制/关卡/曲线，带具体数值。
2. **操作手感**：输入接线、缓冲/土狼时间、判定容差、按键/触控响应，带毫秒。
3. **三档反馈**：普通档 / 重要档 / 重大档各是什么演出，对应 spec §4 行。
4. **内容扩展**：数量红线（关卡数/牌数/武器数/词量等）与红线一句核对「未改核心规则」。
5. **重复游玩价值**：难度阶梯/随机性/记录/成就/重开路径。
6. **视觉语言一致性**：如何落在纸/墨/朱 + 3px 边 + 硬阴影，CSS 是否只写本台私有类。
7. **性能实测**：avg/worst ms、fps、粒子峰值，注明采样环境。
8. **移动端**：390×844（必要时加 844×390）最小可点尺寸、横向溢出、真触控结果。
9. **回归与红线**：r2 探针断言条数与结果、红线逐条 PASS、关闭后 `__loops` 不增长、console error 0。
10. **未解决/遗留**：照抄 notes.md §10。
