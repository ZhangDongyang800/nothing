## 一、四屏设计方案

统一前提：桌面 1600×900 实测。棋盘列宽度由高度反推，`(900−228)×6/7 = 576`，棋盘 576×672；左栏 208、右栏 384、顶栏 56。所有数字均来自样板实测（`over:0 / clipped:[]`）。

### 1. 主界面（`#main`）

**布局结构**：定宽 1040 的两列，居中；顶部无顶栏，底部一条"上一局"账。

- 左列（1fr）：kicker → 朱砂印「守」64/88 + 标题 44px 宋 → 一句定位（15px，30ch）→ 四拍循环（壹招募/贰合兵/叁布阵/肆守，13px，上下发丝线）→ 四条战绩（2×2，label 11 + 值 24 宋）。
- 右列（300px）：地图 kicker → 6×7 缩略棋盘（300×350，带「入」「寨」和 8 个兵字）→ 行动栈（主按钮「开始守卫」→「继续上局」→「局外成长」→ 玩法/设置 → 存档说明）。

**信息层级**：①标题（一眼知道是什么游戏）②主行动（开始）③战绩（我打到哪了）④地图预览（这局长什么样）⑤次要入口。层级靠字号 44→15→24→13 与位置（左→右）固定，不靠装饰。

**颜色**：整屏只有纸三档 + 墨 + 一枚朱砂印 + 棋盘上的朱砂「入」「寨」。战绩数字用墨，不用金——金留给结算的"最佳"。

**图标**：只有一枚字印（守）。没有线符——起始页不需要工具按钮，玩法/设置走文字链接。

**与旧实现的差异及理由**：

| 旧 | 新 | 为什么 |
| --- | --- | --- |
| 三列各自垂直居中，右列是一小块浮岛 | 两列 + 右列一条竖带（地图在上、行动在下、同宽 300） | 旧版右列只有 260 高，与左列 420 高差太多，视觉上是"漂着的一块"；新版顶边对齐、宽同、读起来是一列 |
| 英雄卡 358×265，内容只占 37% | 缩略棋盘替代英雄卡 | 起始页要回答"这局长什么样"，不是"这个英雄长什么样"；棋盘 22 格 + 8 兵一次讲完玩法 |
| 无地图预览 | 6×7 缩略棋盘带「入」「寨」、兵字 | "兵就是文字"是本作概念，缩略图必须写字，否则读成一堆黑方块 |
| 首屏纵向堆叠 | 两列 | 1600 宽下纵向堆叠会把主行动推到第二屏 |

### 2. 择将（`#hero`）

**布局结构**：300 / 1fr / 300 三列，顶部 64px 一条屏内导航（"战前 · 择将 · 点将台" + 返回）。

- 左：英雄列表（4×72），行内 56 字印 + 名 19 宋 + 定位 11 + 右侧状态（出战=朱砂 / 待命 / 0/90 解锁进度）。
- 中：大字区。88 字印 + 名 40 宋 + meta 12 → 4 列键值表（生命/攻击/护甲/射程，label 11 / 值 15）→ 被动 → 主动（带键帽 Q、冷却 38s）→ 阵中联动。段与段之间只有一条发丝线。
- 右：唯一主行动「以此将出战」→ 两条规则说明（11px）→ 两条战绩（20 宋）。

**信息层级**：①是谁（印+名）②四个数（能不能打）③被动/主动（怎么打）④规则（为什么这么打）⑤出战按钮。左右两列都是"读"，只有右列一个"做"。

**颜色**：选中行用纸面 + 3px 朱砂左缘；锁定英雄降墨（`ink-3` 字 + `paper-2` 底），**不用锁图标**。联动标签用朱砂 1px 框。

**图标**：4 枚英雄字印（锋鸢鹭雪）+ 1 个键帽 + 1 条返回线符。键帽只在真实快捷键上出现。

**与旧实现的差异及理由**：

| 旧 | 新 | 为什么 |
| --- | --- | --- |
| 军团 intro 里有键盘词、品质签对比不足 | 键帽只出现在真正的按键（Q），其它文案去键盘化 | 触摸设备读"按 Q"是误导；只有真快捷键才配键帽 |
| 英雄详情一整段文字流 | 4 列键值表 + 三段说明 | 4 个数字要能横向比较（谁护甲高），段落做不到 |
| 属性写成"生命 560·护甲 32"挤一行 | 拆成 4 个字段 | 复合值不可扫读；拆开后 eye 可以只看"射程"列 |

### 3. 战斗（`#battle`）

**布局结构**：顶栏 56 单行 → 三列 208 / 1fr / 384。

- 顶栏：波次（26/34 宋）× 阶段（交战中=朱砂）× 营寨血条（≤300，4px）× 粮/银 × 笔势（朱砂 2px 左线）× 工具组（交战禁用态 / 铁壁 accent / 倍速 / 暂停 / 设置）。下沿 2px 波次进度线。
- 左栏：战场（山道·窄口 + 本波剩余 5/14）→ 敌情（3 枚朱砂 chip + 一句"断笔者优先点名"）→ 笔势（横·第1行 ×3 / 直·E列 ×3）→ 战术构筑（4 枚 chip）→ 下个 Boss（锚底）。
- 中列：Boss 题签 36（名/血条/段）→ 棋盘 576×672（6×7，含行列标尺 A–F / 1–7）→ 读数条 72（字印+名+meta+4 读数+笔势 chip）。
- 右栏：招贤榜（3×112 卡 + 刷新/重金纳贤 + 连招文字动词）→ 点将台（4×72 格 + 一句合成规则）→ 道具（2×40 方）。

**信息层级**：①棋盘（兵在哪、敌在哪、笔势在哪）②顶栏（还能撑多久、还剩几波）③读数条（选中这个是几级、打多少）④右栏（还能招什么）。左栏是"解释"，永远最后读。

**颜色语义**：墨块=我方，朱砂=敌方/危险/当前选中，赭=土路，斜线=未解锁，纸色=空。**一个格子最多 4 个信号**（墨/朱/纸底、品质左缘 3px、等级点、笔势虚线），旧版有 5 个（多一个白块等级）。

**图标**：字印（兵/英雄/资源/道具/强化）+ 线符（倍速、暂停、设置、关闭）。敌方用**朱砂圆**而不是字印方框——形状本身表示敌我。

**与旧实现的差异及理由**：

| 旧 | 新 | 为什么 |
| --- | --- | --- |
| 3 份 CSS 叠补丁，`.lg-card` 出现 333 次 | 一套 `ds-*` | 同一个卡片有 6 套长相，改一处改不动 |
| 选中单位面板在右栏占 232px，选中时才出现 | 读数条常驻棋盘下方 72px | 选中/取消会让右栏内容跳动，玩家手会跟着抖；常驻后零跳动 |
| 1366 右栏 740 塞进 608（132px 被藏） | 右栏内容按"三段 + 页签"重排，全部可见 | 隐藏内容 = 玩家永远不知道有重金纳贤 |
| 1024 顶栏 `.lg-hud-wave` 高 66 溢出 48px 压棋盘 | 顶栏固定 56，内容压缩不重排 | 顶栏是唯一固定高度的横条，任何断点都不许长高 |
| `.lg-tabs` 被 `display:none` | 页签常驻可见 | 桌面玩家进不去兵种/英雄/成就，是功能缺失不是美观问题 |
| 单位格 5 个信号 | 4 个 | 白块等级与底部点重复；留点、去块 |
| 空格有 4 角刻线 + 中心点 | 只留土路中心点 | 空格不需要装饰，需要"这是路" |

### 4. 结算（`#result`）

**布局结构**：960 宽弹层居中，head 56 / body 两栏（340 + 1fr，中缝发丝线）/ foot 64。

- 左栏：朱砂印「破」88 → 「守到第 20 波」28 宋 → 历史最高 27 波 · 差七波（11px）→ 战场 / 领将 两行（label 11 + 值 17）。
- 右栏：本局记录台账 6 行（label / 本局值 15 粗 / 最佳 11 右对齐，最佳用金）→ 最终军团 8 枚 44 格（品质左缘）→ 新成就 2 枚金 chip。
- 页脚：左「再来一局」主按钮，右「局外成长」+「回目录」。

**信息层级**：①结论（守到第几波）②差多少（历史最高）③这一局的数据（6 行台账）④带走了什么（军团/成就）⑤下一步（再来一局）。

**颜色**：只有印是朱砂；最佳记录用金；其它全墨。**结算屏不用红色标题、不用庆祝礼花**。

**图标**：1 枚判词印 + 8 枚兵字印 + 1 条关闭线符。

**与旧实现的差异及理由**：

| 旧 | 新 | 为什么 |
| --- | --- | --- |
| 同一组数（生存/斩敌/伤害）在左栏大数字 + 右侧台账各出现一次 | 左栏只放"这局是什么"（战场/领将），数字全部进台账 | 重复数字会让玩家怀疑"哪个才是真的"，也让一屏信息量翻倍 |
| 弹层五档宽度 680/758/760/830/854 | 480/720/960 三档 | 宽度不统一导致每个弹层的排版都不一样，维护成本按弹层数量线性增长 |
| 页脚"主按钮左、次按钮随机漂" | 主左、次右，两组各成一组 | `margin-left:auto` 同时加在两个按钮上会把空间劈成两半，读起来像三个孤岛 |

## 二、验收机制

分三层：**静态规则（快、每次提交跑）** + **运行时规则（改屏后跑）** + **人工评审（换版本前跑）**。

### 1. 静态：`site/scripts/qa-design-lint.mjs`

不读浏览器，只扫文件，几十毫秒出结果，适合提交前/CI。

| 规则 | 判据 | 级别 |
| --- | --- | --- |
| 裸颜色 | 军团 CSS/HTML 里出现 `#hex` / `rgb(` / `rgba(`（`design/tokens.css` 是唯一豁免，它的职责就是声明字面量） | error |
| 裸字号 | 出现 `font-size:` + 非 `var(--lg-fs-*)` 的字面量；`inherit`、`calc(...)`、`cqw/cqh/vw/vh` 等容器相对单位豁免 | error |
| 非阶梯圆角 | `border-radius:` 出现 0/2/4/999px 以外的值 | error |
| 阴影越界 | `box-shadow` 出现 `blur > 0` 或超过 2 层 | error |
| `!important` | 任何 `!important`（`components.css` 的 `box-sizing` 兜底白名单除外） | error |
| emoji 图标 | `.css/.ts/.html` 里出现 emoji 码点 | error |
| 品质色漂移 | `tokens.css` 的 `--lg-rar-*` 与 `data/rarity.ts` 的 `RARITY_COLOR` 不一致 | error |
| 样板裸值 | `design/legion-ui.html` 的内联 style 里出现 `#hex` 或非阶梯字号 | error |
| 旧文件新增 | `legion-v6.css` / `legion-v7.css` 行数增加 | warn |
| 字号下限 | 军团 CSS 里出现 `font-size` < 10px | warn |
| 重复选择器 | 同名选择器在同一文件出现 > 3 次 | warn |

> 当前基线：`0 error / 1752 warn`（warn 全部落在三份旧 CSS 的迁移债上，是审计证据，不是新违规）。任何一次提交后 error 必须为 0；warn 只许减不许增。

用法：

```powershell
node site/scripts/qa-design-lint.mjs            # 全量（默认 legacy-tolerant，旧三份 CSS 报 warn）
node site/scripts/qa-design-lint.mjs --strict   # 迁移完成后的目标：旧 CSS 也按 error 报
node site/scripts/qa-design-lint.mjs --json     # 给 CI
```

### 2. 运行时：`site/scripts/qa-ui-runtime.mjs`（P1 落地）

用 playwright-core + 本机 Chrome，五档分辨率（1920 / 1600 / 1366 / 1024 / 390×844 / 844×390）逐屏检查：

| 检查 | 判据 |
| --- | --- |
| 横向溢出 | `documentElement.scrollWidth <= clientWidth`，否则报出越界的元素 |
| 垂直裁切 | 所有 `overflow:hidden` 容器的 `scrollHeight > clientHeight + 2` |
| 顶栏越界 | `.ds-hud` 高度 = 56（桌面）/ 三行且 ≤140（竖屏），不遮棋盘 |
| 首屏主行动可见 | `主按钮.rect.bottom <= innerHeight`（起始屏、结算屏） |
| 触控命中 | 所有 `button / a` 的 rect 边长 ≥ 44（`pointer:coarse` 模拟） |
| 字号下限 | 遍历可见文本节点，最小 `font-size >= 11px`（`.ds-kbd` 允许 10） |
| 棋盘完整性 | 棋盘 rect 宽高比 = 6/7 ±1%，且完全在视口内 |
| 卡片空白 | 卡片内容高度 / 卡片高度 ≥ 70%（旧版 37%） |

### 3. 人工评审清单（每版一次，10 分钟）

1. 遮住所有文字，只看色块：能否一眼分出"我方 / 敌方 / 路 / 未解锁"？
2. 只看字号大小：能否排出 3 级层级？
3. 把任一屏缩到 1024，主行动还在第一屏吗？
4. 数一数这一屏有几个"卡片底"：超过 2 个就是过度分块。
5. 每个图标都能说出一句"它表示 X"吗？有一个说不出的就删。
6. 同一数字是否出现两次？出现即删其中一处。
7. 关闭 hover/动效，界面是否仍然完整可读？（触屏等价性）

## 三、分阶段实施计划

原则：**先立规矩，再换组件，最后逐屏重做**。每一步都有可回滚的边界，不允许"一把梭"。

### P0 · 冻结并接入（0.5 天，不动界面）

- 新增 `design/tokens.css`、`tokens.ts`、`icons.ts`、`components.css`（已完成，本阶段产物）。
- `legion-v6.css` / `legion-v7.css` 标记 `/* FROZEN: 迁移期只删不加 */`；新代码一律 `ds-*`。
- 接 `qa-design-lint` 到提交前检查（`--allow-legacy` 模式，只报 warn 不阻断）。
- **出口**：lint 全绿（legacy 模式）；游戏行为零变化（跑一局 20 波）。

### P1 · 抽象现役组件（1–1.5 天，仍不动视觉）

- 把现役 `ui.ts` 里重复的 DOM 模板抽成 `renderXxx()`（卡、槽、读数、弹层头/脚），输出 `ds-*` 类名但**保留旧 CSS 的视觉**作为过渡类。
- canvas 端 `draw.ts` 的颜色改读 `tokens.ts`（PAPER / SEAL / GOLD 三组），消除 DOM 与 canvas 两套色。
- **出口**：截图逐像素对比，P1 前后差异 < 2%（只允许颜色微差）；lint 0 error。

### P2 · 逐屏替换（3–4 天，按价值排序）

1. **战斗屏**（先做，信息密度最高）：顶栏单行 → 读数条 → 右栏三段 → 左栏。删掉"右栏选中单位面板"。
2. **招贤/点将**：卡片四段化、点将格 72、拖拽预判。
3. **择将屏**：4 列键值表、英雄列表行。
4. **结算 + 起始屏**：弹层三档、起始两列。

每屏替换完立即跑运行时检查 + 截一张 `.qa/keep/战斗-v2.png` 存档。

- **出口**：五档分辨率 `over:0 / clipped:[]`；最小字号 ≥11；卡片内容占比 ≥70%。

### P3 · 手机两断点（1–1.5 天）

- 竖屏：顶栏三行（order 调序）、棋盘 300（格 50）、读数条两行、抽屉两页签。
- 横屏触屏：右栏固定 300，顶栏单行。
- **出口**：390×844 与 844×390 首屏都含"棋盘 + 读数 + 招贤卡 + 买按钮"；无横向滚动。

### P4 · 删债（0.5 天）

- 删 `legion-v6.css` / `legion-v7.css`（先 grep 确认无引用）、删 `legion.css` 里被 `ds-*` 覆盖的规则。
- 把 `--lg-*` 里只为旧类服务的变量清掉。
- **出口**：军团 CSS 总行数从 5378 → ≤2500；重复选择器 0；lint 全绿（非 legacy 模式）。

### 风险与回滚

| 风险 | 处理 |
| --- | --- |
| 换读数条时战斗逻辑读到旧节点 | 先加 `data-ui` 属性做稳定选择器，再换 DOM；逻辑层只认 `data-ui` |
| 手机棋盘变小导致误触 | 格高 50 保底；触屏命中检查跑一遍 |
| 一次改多屏无法定位回归 | 一屏一提交，提交信息写 `ui(battle): ...`；`.qa/keep` 留对照图 |
| 旧 CSS 与新 CSS 同权重打架 | 新类前缀 `ds-`，与 `lg-` 不重叠；冲突时不给旧类加 `!important`，直接删旧规则 |
